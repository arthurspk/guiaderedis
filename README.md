## 🗺️ Roadmap

- [roadmap.sh — Redis](https://roadmap.sh/redis) — Trilha visual e interativa dedicada ao Redis: estruturas de dados, persistência, replicação e cluster.
- [roadmap.sh — Backend Roadmap](https://roadmap.sh/backend) — Roadmap mais amplo de back-end, com cache e Redis como uma das etapas essenciais.
- [Redis — Release Notes (GitHub)](https://github.com/redis/redis/releases) — Notas de lançamento oficiais de cada versão do Redis, incluindo as novidades de 8.0 (2024).

**Trilha resumida** (siga na ordem; cada etapa tem recursos nas seções abaixo):

1. **Fundamentos** — o que é um banco chave-valor em memória, quando usar cache vs. banco principal, e como instalar o Redis localmente ou via Docker.
2. **Estruturas de dados** — strings, lists, hashes, sets, sorted sets e os comandos de cada uma; é a base de tudo no Redis.
3. **Expiração e cache** — TTL, políticas de eviction (`maxmemory-policy`), padrões de cache (cache-aside, write-through).
4. **Pub/Sub e filas** — mensageria simples com `PUBLISH`/`SUBSCRIBE` e filas com listas ou com Streams.
5. **Streams** — `XADD`, `XREAD`, consumer groups; o jeito Redis de processar eventos em tempo real.
6. **Persistência** — RDB (snapshots) e AOF (append-only file), e como escolher entre eles (ou combinar os dois).
7. **Transações e scripts** — `MULTI`/`EXEC`, `WATCH` e scripts Lua para operações atômicas.
8. **Alta disponibilidade e escala** — replicação, Sentinel (failover automático) e Redis Cluster (particionamento horizontal).
9. **Segurança e administração** — ACLs, TLS, `redis-cli`, monitoramento e boas práticas de produção.
10. **Redis Stack e IA** — RedisJSON, busca full-text (RediSearch) e busca vetorial para RAG e aplicações de IA.

## 🤖 IA na prática

Redis deixou de ser só "o cache mais rápido" para virar também "onde a IA guarda memória": com a busca vetorial nativa, o mesmo banco que guarda sessões e contadores guarda também os embeddings usados em busca semântica e RAG, com latência de milissegundos. A regra de ouro continua a mesma: a IA propõe o comando ou a modelagem, você confere com dados reais antes de confiar.

**Para aprender**
- Cole um comando Redis que você não entende (ex.: `ZADD`, `XREADGROUP`) e peça para a IA explicar parâmetro por parâmetro e comparar com alternativas.
- Cole um erro (ex.: `OOM command not allowed` ou `WRONGTYPE Operation against a key`) junto com o trecho de código e peça a causa e duas formas de corrigir.
- Descreva um problema (ex.: "preciso de um rate limiter por usuário") e peça a modelagem em Redis — depois critique: essa estrutura de dados é a mais eficiente? existe risco de crescer sem limite?
- Peça exercícios com gabarito sobre o tópico que está estudando (TTL, transações, cluster) simulando cenários reais de cache.

**Para trabalhar**
- **Servidores MCP** conectam Cursor, Claude Code ou Copilot direto ao seu Redis: o assistente lê chaves, roda comandos e analisa uso de memória. Use com uma instância de desenvolvimento e nunca em produção sem revisão — o [Redis MCP Server](https://github.com/redis/mcp-redis) é o servidor oficial, mantido pela própria Redis Inc.
- Use assistentes de IA para: escrever scripts Lua, gerar chaves e TTLs consistentes, criar índices de busca a partir de queries lentas, documentar padrões de cache e escrever testes automatizados.
- **Busca vetorial nativa** transforma o Redis em banco vetorial: embeddings, busca por similaridade e RAG rodam direto no mesmo banco que guarda cache e sessões, sem precisar de um banco vetorial dedicado.
- **LangChain + Redis** é uma combinação comum para RAG: o Redis guarda tanto o cache de respostas do LLM quanto o índice vetorial usado na busca semântica.

**Limites e boas práticas**
- LLMs **inventam comandos, flags e módulos** que não existem ou já foram descontinuados. Sempre confira na [referência oficial de comandos](https://redis.io/docs/latest/commands/) antes de rodar em produção.
- Um comando "correto" pode ser **lento ou perigoso** em chaves grandes (ex.: `KEYS *` em produção). Peça à IA uma alternativa segura (`SCAN`) e teste em staging.
- Modelagem de dados no Redis não tem uma resposta única: a IA sugere uma estrutura, mas só você conhece o padrão de acesso real da sua aplicação.
- **Nunca cole dados pessoais ou segredos** (senhas, strings de conexão, dados de clientes) em ferramentas de IA sem a política de segurança da sua empresa. Lembre-se da LGPD.
- Entenda o que você executa: em produção e em entrevista técnica, o comando é seu.
